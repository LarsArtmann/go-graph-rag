## e) WHAT WE SHOULD IMPROVE!

1. **Challenge policy, not just facts.** When enforcing a rule costs a day of whack-a-mole and the
   ecosystem has visibly moved (v2 in stdlib, v1 a shim), the correct escalation is "should we
   flip the rule?" — a (g)-question slot exists in every report; it went unused for this.
2. **Never `git add -A` in a multi-writer repo.** Stage named files; review `git status` as the
   last act before committing.
3. **Polling loops must abort loudly on empty ID** instead of cascading into `gh run watch ""` →
   false red. Or skip polling: `gh run list --workflow=X --limit N` on suspicion, first, always.
4. **View-immediately-before-edit** in this repo is now a HARD rule for me (daemon + dprint mtimes);
   assume no file is as last seen.
5. **Multi-writer serialization**: today two sessions + a daemon wrote CHANGELOG/TODO/release
   files concurrently around two releases. Nothing clobbered, but the margin was luck plus
   re-reads. Either serialize sessions per repo or partition file ownership explicitly.
